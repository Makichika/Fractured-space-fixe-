INSTRUCTIONS FOR EMPLACEMENT
Fractured Space client fixes
Author: Makichika

======================================================================
PART 1 - INSTALLATION
======================================================================

STEP 1 - CLOSE THE GAME AND DOWNLOAD THE FILES

1. Close Fractured Space completely.
2. On GitHub, click Code > Download ZIP.
3. Extract the ZIP to a folder outside the game.
4. Back up each existing game file before replacing it.

STEP 2 - FIND YOUR GAME FOLDER

In Steam: right-click Fractured Space > Manage > Browse local files.

The game folder is named Space and contains the spacegame folder.
The usual location is:
C:\Program Files (x86)\Steam\steamapps\common\Space

Use your actual Steam location if yours is different.
Every path below starts at this Space folder.

STEP 3 - COPY THE FILES TO THEIR MATCHING LOCATIONS

Copy the individual files listed below into the matching folders in your
game. Accept replacement only for those matching filenames.

Do not copy the whole downloaded repository into the game.
Do not create another Space folder inside your existing Space folder.
No manual editing is needed.

FOLDER STRUCTURE

Space/
    spacegame/

            Win64/
                Fractured Space.exe
        Content/
            Paks/

A. DRAFT MENU - 3 FILES

Copy these files from the download to the same paths in your game:
Space\spacegame\Content\UIResources\frontend\drafting\drafting-script.js
Space\spacegame\Content\UIResources\frontend\drafting\mode-selector.js
Space\spacegame\Content\UIResources\frontend\drafting\drafting-style.css

Default destination folder:
C:\Program Files (x86)\Steam\steamapps\common\Space\spacegame\Content\UIResources\frontend\drafting

These files update the Ready button, mode names, artwork and list scrolling.

B. GAME EXECUTABLE - 1 FILE

Copy this file from the download to the same path in your game:
Space\spacegame\Binaries\Win64\Fractured Space.exe

Default destination folder:
C:\Program Files (x86)\Steam\steamapps\common\Space\spacegame\Binaries\Win64

Replace the existing Fractured Space.exe. Keep its exact filename.
This one file includes the draft player list, missile warning and effect
countdown fixes. Game-time countdowns require a compatible server.

C. ADDITIONAL FIXES - 3 PAK FILES

Copy these files from the download to the same paths in your game:
Space\spacegame\Content\Paks\Makichika_MapJamming_P.pak
Space\spacegame\Content\Paks\Makichika_VenturerSkins_P.pak
Space\spacegame\Content\Paks\Makichika_ProtectorShield_P.pak

Default destination folder:
C:\Program Files (x86)\Steam\steamapps\common\Space\spacegame\Content\Paks

- Makichika_MapJamming_P.pak: map jamming display fix.
- Makichika_VenturerSkins_P.pak: Venturer skin fix.
- Makichika_ProtectorShield_P.pak: Protector shield field visual fix.

Each PAK can be installed separately. Add it alongside the existing PAKs.
Keep the original BP.pak and the other installed PAK files.

D. OPTIONAL SERVER LIST GROUPING - 1 FILE

Copy this file only if you want heart-prefixed servers first, Tiger-prefixed
servers second, and the remaining servers last:
Space\spacegame\Content\UIResources\frontend\views\startgame\startgame-script.js

Default destination folder:
C:\Program Files (x86)\Steam\steamapps\common\Space\spacegame\Content\UIResources\frontend\views\startgame

Replace the matching startgame-script.js after backing it up.
The received order is kept within each group. No blank rows are added.
This optional file can be installed on its own.

STEP 4 - RESTART THE GAME

Start Fractured Space with your usual launcher.
A complete game exit and relaunch is needed to load new PAK files.
Changing server or map is not enough.

Each player installs the client files on their own computer.
Server gameplay rules, timers, teams and bots are configured separately.

IF YOU ALREADY USE OTHER CLIENT MODIFICATIONS

The executable and JavaScript/CSS files are complete replacement files.
Replacing them also replaces any custom changes inside those same files.
This matters especially if your startgame-script.js has custom LAN features.
Keep your backups. Other client builds have not been verified.

HOW TO UNINSTALL

1. Close the game completely.
2. Restore any replaced files from your backups.
3. To remove an added PAK fix, remove only its matching Makichika PAK file.
   If you replaced an older version of that PAK, restore your backup instead.
4. Restart the game.

Restore startgame-script.js to undo the optional server grouping; do not
delete the game script. Keep BP.pak.

ABOUT THE FOLDERS ON GITHUB

GitHub may show UIResources/frontend/drafting on one clickable line.
They are separate folders inside one another. Download ZIP keeps them so.

B. Incoming missile icon and alert cleanup fix (19 October 2026)

The client can retain a destroyed missile briefly to finish its particle
trail. Its red HUD icon and incoming warning beep could remain active during
that visual cleanup. The icon and sound queries now ignore destroyed or
trail-cleanup missiles without waiting for the retained actor to disappear.
Another living missile can still trigger its warning. The original warning
configuration is preserved; the fix does not permanently disable the alert
or require a respawn between successive missile salvos.

This is a client fix installed by each player. It does not change server
files, missile damage, point defense, particle trail lifetime or audio banks.
Slowing the server can prolong game-time cleanup; that alone does not prove
the HUD cleanup is controlled by the server.

uses game time only after the connected server announces its matching clock
capability through the existing reliable ClientMessage RPC. The announcement

PALADIN PURGE AND EFFECT CLOCKS

Installed on the five Makichika server profiles; server files are not supplied
as client downloads. The standard Paladin Purge Torpedo acts on the hit ship.

Allied receiver:
Remove negative statuses immediately and reject new negative statuses for
five game seconds. Positive allied statuses remain allowed.

Enemy receiver:
Remove positive statuses, including Shielded protection, and reject new
positive statuses for five game seconds. Negative statuses remain allowed.
Gamma objective reward category 20 is exempt. Gamma Spotted detection is
separate and remains a negative status. This is status immunity, not immunity
to ordinary damage. Paladin Plasma Field direct damage is unchanged.

During an enemy Purge window, abilities granting only personal positive
effects are blocked before normal activation costs. Shared self-and-allies
abilities remain usable; the purged ship's positive self-benefit is rejected
while other eligible recipients can still receive their benefits. Protector
Shielding can therefore continue serving nearby allies while its purged owner
loses its personal shield. The separate client pak preserves the field visual.

The duration is five seconds for Purge, status rejection, personal ability
blocking and replicated countdown metadata. The earlier three-second revision
is retained privately as a reserve and is not the active server setting.
The duration RPC carries a multiplier adjustment, not an absolute duration.

Named FStatusEffect creation and expiry comparisons, plus the private Purge
window, now use UWorld game time at offset 0x900 instead of real time at 0x908.
This follows intentional MATCH SPEED slow motion. The separate timed ShipPawn
modifier queue and area/direct-damage lifetimes were not converted; this is
not a claim that every timed game mechanic was changed.

The server announces compatible clocks with the existing reliable
ClientMessage RPC, empty text, message type Makichika_Status_GameClock_v1
and lifetime zero. The client executable supplied here uses that capability.
Clients without the clock update can show a mismatched countdown in slow
motion while server gameplay remains authoritative.

A post-draft PvP crash in the first clock revision was traced to the new
capability scan reading World+0x140 as GameState. The installed repair uses
the existing native GetGameState function at RVA 0x13DD360, whose native code
reads World+0xF8. Native reflection independently confirms PlayerArray+0x330.
The old failing revision is historical and must not be restored as a fix.

Dedicated executable SHA256 recorded for this server revision:
79BDAA2C2CEA6314E4B86F51C2AF12557578DC2F3F97F6F81435AC456AD29A5C
windows_host.py SHA256 recorded for this server revision:
B4572750708D8FD49373D25A1FE15022BB8229967860E2CF3EC3235C9D7CAD10

For this server revision, the manager edit only updated the accepted executable hash. The five profile
configurations, launchers and other manager files were preserved. Existing
authentication and automatic server management remain in place.

Verification: 198 native x64 assertions at two simulated ASLR bases, including
a regression that reproduces the old invalid GameState path; 16 native bool
ownership assertions; PE/preservation/unwind checks and an owned dedicated
startup against loopback sessions. These checks do not establish exhaustive
ship/status coverage, all Gamma statistics, actual shield damage reduction
or every multiplayer and slow-motion sequence.

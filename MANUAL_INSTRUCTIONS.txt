INSTALLATION

Close Fractured Space. Back up each file before replacing it.
Download this repository with Code > Download ZIP, then extract it.
Do not copy the ZIP or the whole downloaded folder into the game.
Copy only the individual files to the exact matching destinations below.

The included Space folder shows the full path from the game folder.
Your own Space folder is the one containing spacegame.
Default Steam game folder:
C:\Program Files (x86)\Steam\steamapps\common\Space
Use your actual installation folder if it is different.
Do not create a second Space folder inside your existing Space folder.

If Makichika_MapJamming_P.pak was newly added, remove that file to undo its fix.

or rename it to Makichika_VenturerSkins_P.pak.disabled. Keep the original BP.pak.

4. FRACTURED SPACE.EXE

A. Drafting player list fix (retained)

Fixes the cached drafting player list. The original client could keep a cached
list containing only the first player even after more players or bots arrived.
The new guard rejects an empty cache or a count different from the current
PlayerArray count, allowing the existing native drafting Tick to rebuild it
when its original initialization and readiness checks permit.

Exactly 36 executable bytes change in two locations. File size, PE sections,
exception/runtime tables, Ready flags, player IDs, stages and timers are preserved.

After:

The guard compares GameState+0x458 (cached count) to GameState+0x338

and resumes at RVA 0x3B4005, retaining the original individual-ID checks.

B. Incoming missile icon and alert cleanup fix (19 October 2026)

The client can retain a destroyed missile briefly to finish its particle
trail. Its red HUD icon and incoming warning beep could remain active during
that visual cleanup. The icon and sound queries now ignore destroyed or
trail-cleanup missiles without waiting for the retained actor to disappear.
Another living missile can still trigger its warning. The original warning
configuration is preserved; the fix does not permanently disable the alert
or require a respawn between successive missile salvos.

This is a client fix installed by each player. It does not change server
files, missile damage, point defense, particle trail lifetime or audio banks.
Slowing the server can prolong game-time cleanup; that alone does not prove
the HUD cleanup is controlled by the server.

Relative to the previously supplied executable D3977E731EE5636859174B323B761A7F510D8C76FC64FB904E35BD1B1CE185F6,
39 bytes change across the following four regions. The drafting HUD
correction above remains byte-identical. File size remains 62232064 bytes;
PE sections and existing exception/runtime tables are preserved.

6. MAKICHIKA_VENTURERSKINS_P.PAK

Corrects material bindings for the fourteen existing Venturer skin definitions.
The original Swarm bindings placed the neutral silver material on the main
hull panels and the blue skin material on small structural parts. Swarm and
Swarm II also had replacement bindings only for the highest-detail model.

The fix resolves the original skin palettes to the current mesh material
slots and supplies consistent bindings across the four detail levels.
Lower-detail models merge some surface regions; exact fine-detail equivalence
between every distance and every historical skin image has not been verified.

Only BP_SHP_MID_M00_C018_Venturer is overridden: one uasset/uexp pair.
One component's skin bindings change; the other 113 export payloads are
byte-identical. Existing textures, mesh geometry and skin identifiers remain
unchanged. Other ships, the executable and server files are not modified.

Offline checks passed for 366 bindings, package round trips and pak index/
payload integrity. The user reported the repaired appearance working in a
gameplay test. This is not an exhaustive visual test of all fourteen skins
at every distance or proof of installation on every other client build.

Supplied pak size: 139180 bytes.

INSTALLATION

Close Fractured Space. Back up each file before replacing it.
Download this repository with Code > Download ZIP, then extract it.
Do not copy the ZIP or the whole downloaded folder into the game.
Copy only the individual files to the exact matching destinations below.

The included Space folder shows the full path from the game folder.
Your own Space folder is the one containing spacegame.
Default Steam game folder:
C:\Program Files (x86)\Steam\steamapps\common\Space
Use your actual installation folder if it is different.
Do not create a second Space folder inside your existing Space folder.

9. SERVER-SIDE PALADIN PURGE AND EFFECT CLOCK CHANGES

Installed on the five Makichika server profiles; server files are not supplied
as client downloads. The standard Paladin Purge Torpedo acts on the hit ship.

Allied receiver:
Remove negative statuses immediately and reject new negative statuses for
five game seconds. Positive allied statuses remain allowed.

Enemy receiver:
Remove positive statuses, including Shielded protection, and reject new
positive statuses for five game seconds. Negative statuses remain allowed.
Gamma objective reward category 20 is exempt. Gamma Spotted detection is
separate and remains a negative status. This is status immunity, not immunity
to ordinary damage. Paladin Plasma Field direct damage is unchanged.

During an enemy Purge window, abilities granting only personal positive
effects are blocked before normal activation costs. Shared self-and-allies
abilities remain usable; the purged ship's positive self-benefit is rejected
while other eligible recipients can still receive their benefits. Protector
Shielding can therefore continue serving nearby allies while its purged owner
loses its personal shield. The separate client pak preserves the field visual.

The duration is five seconds for Purge, status rejection, personal ability
blocking and replicated countdown metadata. The earlier three-second revision
is retained privately as a reserve and is not the active server setting.
The duration RPC carries a multiplier adjustment, not an absolute duration.

Named FStatusEffect creation and expiry comparisons, plus the private Purge
window, now use UWorld game time at offset 0x900 instead of real time at 0x908.
This follows intentional MATCH SPEED slow motion. The separate timed ShipPawn
modifier queue and area/direct-damage lifetimes were not converted; this is
not a claim that every timed game mechanic was changed.

The server announces compatible clocks with the existing reliable
ClientMessage RPC, empty text, message type Makichika_Status_GameClock_v1
and lifetime zero. The client executable supplied here uses that capability.
Clients without the clock update can show a mismatched countdown in slow
motion while server gameplay remains authoritative.

A post-draft PvP crash in the first clock revision was traced to the new
capability scan reading World+0x140 as GameState. The installed repair uses
the existing native GetGameState function at RVA 0x13DD360, whose native code
reads World+0xF8. Native reflection independently confirms PlayerArray+0x330.
The old failing revision is historical and must not be restored as a fix.
